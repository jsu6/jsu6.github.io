RQ2: the 29 confirmed bypasses, in your own browsers

Our slices predict 33 APIs that read information a Brave defense protects but escape its default (Standard) hooks. In Brave 1.92.144, 29 of them returned the same value as Brave with fingerprinting protection off, on two sites and in two sessions. This page reads those 29 with the probe code of our study, so you can repeat the check in real browsers and on real devices.

Nothing leaves this page. Readings stay in this browser's local storage or move by copy and paste. Hooks as in Brave 1.92.144 (brave-core aeb45b6b); Chromium source 150.0.7871.186.

How to check

  1. Scroll the mouse wheel a few notches inside this box (three of the APIs are wheel events).
    scroll here…
  2. Reference. Keep the window smaller than the screen and page zoom at 100% (Brave's screen hook changes nothing when the window is as large as a common screen size). In Brave, open Shields for this site, turn Block fingerprinting off, reload, scroll the box, and press Run, then Save as reference. Allow the window-management prompt (three ScreenDetailed rows need it).
  3. Test. Turn Block fingerprinting back on (Standard), reload, scroll the box, and press Run. The table compares the two. Run again in a new window, or after restarting Brave, to see per-session noise.
  4. Other devices and browsers (optional). Press Copy readings on each, paste them here with a label, and press Add. The last column counts distinct values, which shows whether an API tells setups apart.
A bypass is confirmed when, in Brave Standard, the API returns the reference value (Shields off) on every repeat, and Brave's defense is active, shown by a sibling API it hooks at the default level returning a different value. For the eight Strict-only rows, Brave does not hook the API in Standard by design; set brave://flags/#brave-show-strict-fingerprinting-mode and choose Strict to see the hook act. The study tag says what our own run showed beyond agreement: knob (follows a setting we varied, so it carries information), Strict (rewritten at Strict, so the probe sees a hook act), or none (the same value in every configuration we ran).
