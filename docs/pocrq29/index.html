RQ2: confirmed bypasses among the 29

In Brave 1.92.144, 29 of the 33 bypasses our slices predict returned the same value as Brave with protection off. A bypass is confirmed here only when it reads the same information as an API Brave hooks: this page reads each piece of information both ways and compares Brave with Chromium. Four of the 29 pair with a hooked API this way, without a permission or a user event: the canvas pixels fillText draws, the audio samples startRendering renders, and the screen size through VisualViewport and innerWidth in fullscreen. The other 25 read information Brave does not hide in its default profile, or need a permission or a user event.

Nothing leaves this page, and it asks for no permission. Results move between the two windows only when you copy and paste them. Hooks as in Brave 1.92.144 (brave-core aeb45b6b); Chromium source 150.0.7871.186.

How to check

  1. In both browsers (Brave with Shields at their default, and Chromium or Chrome, on the same machine and display, with windows smaller than the screen and page zoom at 100%), press Run. It enters fullscreen for a moment to measure the screen.
  2. In Chromium, press Copy results.
  3. In Brave, paste them and press Compare.
A bypass works when both hold in Brave: the hooked API returns a different value from Chromium's (the hook is active), and the other API, which reads the same information another way, returns Chromium's value of the hooked API (the hook missed it). The last column is the end both slices share.

How each works

Canvas text pixels

Hook: Brave adds per-site noise to the pixels getImageData returns. Other API: the pixels fillText drew, copied into WebGL (createImageBitmap, texImage2D) and read with readPixels; Brave's WebGL read-back hook acts only at Strict. Our slices grade fillText as reaching the canvas pixels around Brave's canvas hooks. The text is drawn on an opaque background, so both reads return the same bytes in Chromium. Each value is a hash of the raw pixels.



Rendered audio samples

Hook: Brave adds per-site noise to the samples AudioBuffer.getChannelData (and
copyFromChannel) returns. Other API: the samples OfflineAudioContext.startRendering
produced, played into a second offline context, where an AudioWorklet sums them without calling an
AudioBuffer method. The two slices share only a feature flag
(WebAudioConfigurableRenderQuantumEnabled): the samples are computed in the renderer and have no source of
their own, so this row tests the consequence directly.




Screen size

Hook: Brave hands Screen a copy of the screen information with the size replaced by the
smallest common desktop size at least as large as the window. Other APIs: in fullscreen the visual viewport and
the window are the screen, and visualViewport and innerWidth read the same screen information
(the ScreenInfos the browser sends the renderer) without that hook. Run enters fullscreen for a moment; it needs page zoom at 100%. With a window as
large as a common-size screen, Brave's replacement equals the real size and the hook changes nothing: make the window
smaller than the screen and reload, in both browsers.





In numbers


Seeded with the 100 APIs whose slices we built by hand, our analysis finds 61 APIs that read information a
Brave defense protects; 33 of them reach it past the hooks that act in Brave's default profile. In Brave 1.92.144
(two sites, two sessions each), 29 of the 33 returned the value Brave returns with protection off. The four on
this page also read the same value as an API Brave hooks.
