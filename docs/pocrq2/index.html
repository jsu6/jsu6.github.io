RQ2 proofs of concept: Brave protects APIs, not information

Brave hides fingerprinting information by changing what the specific APIs it hooks return. Our slices show other APIs that end at the same source as a hooked API, the place where the information enters the renderer, without passing the hook. This page reads each piece of information both ways and compares Brave with Chromium.

Nothing leaves this page, and it asks for no permission. Results move between the two windows only when you copy and paste them. Hooks as in Brave 1.92.144 (brave-core aeb45b6b); Chromium source 150.0.7871.186.

How to check

  1. In both browsers (Brave with Shields at their default, and Chromium or Chrome, on the same machine and display, with windows smaller than the screen and page zoom at 100%), press Run. It enters fullscreen for a moment to measure the screen.
  2. In Chromium, press Copy results.
  3. In Brave, paste them and press Compare.
A bypass works when both hold in Brave: the hooked API returns a different value from Chromium's (the hook is active), and the route, which reads the same information another way, returns Chromium's value of the hooked API (the hook missed it). The last column is the end both slices share.

How each works

Canvas pixels

Hook: Brave adds per-site noise to the pixels in getImageDataInternal and in ToDataURLInternal, before it encodes the image. Route: transferToImageBitmap turns the same canvas into an ImageBitmap without passing either hook, and WebGL reads it back (texImage2D, readPixels); Brave's WebGL read-back hook acts only at Strict. In the ground-truth slices all three end at the canvas pixels mapped back from GPU memory (the paper's motivating example); in the automatic slices of the 305-API run all three stop one step earlier, at the image copied from those pixels, recorded as a Skia library boundary rather than a source. Every value is a hash of raw pixels; toDataURL's PNG is decoded without a 2D read, so the noise Brave put in it survives.



Rendered audio samples

Hook: Brave adds per-site noise to the samples AudioBuffer.getChannelData (and
copyFromChannel) returns. Route: the samples OfflineAudioContext.startRendering
produced, played into a second offline context, where an AudioWorklet sums them without calling an
AudioBuffer method. The two slices share only a feature flag
(WebAudioConfigurableRenderQuantumEnabled): the samples are computed in the renderer and have no source of
their own, so this row tests the consequence directly.




Screen size

Hook: Brave hands Screen a copy of the screen information with the size replaced by the
smallest common desktop size at least as large as the window. Route: in fullscreen the visual viewport is the
screen, and visualViewport reads the same screen information (the ScreenInfos the browser sends
the renderer) without that hook. Run enters fullscreen for a moment; it needs page zoom at 100%. With a window as
large as a common-size screen, Brave's replacement equals the real size and the hook changes nothing: make the window
smaller than the screen and reload, in both browsers.





In numbers


Seeded with the 305 APIs Chromium marks [HighEntropy], our analysis finds 233 APIs that read
information a Brave defense protects. A hook that acts at Brave's default level sits on the path of 7; the
other 226 reach the same information without passing one. In Brave 1.92.144 (two sites, two sessions each),
92 of the 226 returned the value Brave returns with protection off, 49 leaked through WebGL only (canvas
drawing calls), 36 were rewritten after all, 46 could not be checked by a page, and 3 are
indistinguishable on our machine.
