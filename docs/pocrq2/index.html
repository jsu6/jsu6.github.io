RQ2 proofs of concept: defenses that protect APIs, not information

Minimal pages behind RQ2 of the paper Slicing to the Roots. Each page prints the exact code it runs and only shows values on the page; nothing is sent anywhere. Open a page in Chromium or Chrome first, copy the readings, then open it in Brave (Shields at their default) on the same machine and paste them to compare.

What we found

Seeded with the 305 APIs Chromium marks [HighEntropy], the static analysis finds 233 APIs that read information a Brave defense protects. In Brave's default (Standard) level a hook sits on the path of 7; the other 226 reach the same information without a hook that acts at Standard: they are predicted to circumvent it. In Brave 1.92.144, two sessions on two sites each:

  • 92 of the 226 returned exactly the value Brave returns with fingerprinting protection off (leaked);
  • 49 leaked partly: the canvas drawing calls (arc, fillRect, strokeText, …), whose pixels are farbled through getImageData but read unchanged through WebGL;
  • 36 were rewritten after all (the prediction missed the hook), and 49 could not be checked here (paint worklets, hardware, permission prompts, or values this machine cannot tell apart).

The 305-API seeds use the full run's slices, half of them truncated, so the information a defense protects is broad and one API often counts under several defenses; the per-page counts below overlap.
