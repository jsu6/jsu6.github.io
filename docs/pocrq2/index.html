RQ2 proofs of concept: Brave protects APIs, not information

Brave hides fingerprinting information by changing what the specific APIs it hooks return. Our slices show other APIs that end at the same source as a hooked API, the place where the information enters the renderer, without passing the hook. This page reads each piece of information both ways and compares Brave with Chromium.

Nothing leaves this page, and it asks for no permission. Results move between the two windows only when you copy and paste them. Hooks as in Brave 1.92.144 (brave-core aeb45b6b); Chromium source 150.0.7871.186.

How to check

  1. In both browsers (Brave with Shields at their default, and Chromium or Chrome, on the same machine), press Run.
  2. In Chromium, press Copy results.
  3. In Brave, paste them and press Compare.
A bypass works when both hold in Brave: the hooked API returns a different value from Chromium's (the hook is active), and the route returns Chromium's value (the hook missed it). The last column is the source both slices end at.

How each works

Canvas pixels

Hook: Brave adds per-site noise to the pixels in getImageDataInternal and in ToDataURLInternal, before it encodes the image. Route: transferToImageBitmap turns the same canvas into an ImageBitmap without passing either hook, and WebGL reads it back (texImage2D, readPixels); Brave's WebGL read-back hook acts only at Strict. All three slices end at the canvas pixels mapped back from GPU memory (the paper's motivating example). Every value is a hash of raw pixels; toDataURL's PNG is decoded without a 2D read, so the noise Brave put in it survives.



Audio output device

Hook: Brave adds per-site noise to the samples AudioBuffer.getChannelData returns.
Routes: sampleRate and baseLatency of an AudioContext. Their slices and
getChannelData's end at the same source, the output device's AudioParameters (its sample rate
and buffer size), and neither passes a Brave hook.




Screen

Hook: Brave hands Screen a copy of the screen information with the size replaced by a common
desktop size. Routes: devicePixelRatio and screen.orientation read the same screen
information (the ScreenInfo the browser sends the renderer) without that hook;
screen.colorDepth passes the hook, but the hook keeps the depth.




Plugins

Hook: Brave renames the PDF plugin in navigator.plugins and adds two random plugins.
Route: navigator.pdfViewerEnabled reads the same plugin list without the hook.





In numbers


Seeded with the 305 APIs Chromium marks [HighEntropy], our analysis finds 233 APIs that read
information a Brave defense protects. A hook that acts at Brave's default level sits on the path of 7; the
other 226 reach the same information without passing one. In Brave 1.92.144 (two sites, two sessions each),
92 of the 226 returned the value Brave returns with protection off, 49 leaked through WebGL only (canvas
drawing calls), 36 were rewritten after all, 46 could not be checked by a page, and 3 are
indistinguishable on our machine.
